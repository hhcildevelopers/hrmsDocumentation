# 8. Common Errors & Solutions

[← Handbook](README.md)

Use this page when a screen shows an error, a button is unavailable, or a punch is not confirmed. The exact words can vary by language and portal. On the Field Portal, **Details for supervisor** may show a technical code; employees normally need the plain-language message instead. A red/amber message is not proof that attendance was recorded. Check **Punches** for the final server result.

**Before trying again:** check the selected company, the correct account, phone internet, and the date/time of the duty. Tap **Refresh** once. If a punch may already have been sent, check its result before attempting another. Do **not** clear browser storage or uninstall the Field Portal when punches are waiting to sync: that can erase the only local copy. Never send a password, one-time password, full Aadhaar/PAN number, or bank account number to support.

| What you see | Meaning and likely cause | What you should do | When to ask for help; HR/Admin action |
| --- | --- | --- | --- |
| **Invalid username or password / Could not sign in** | The identifier/password is wrong, the account is inactive, or it is for a different portal. For privacy, the sign-in page does not reveal which one. | Use **username** for Admin, **Employee Code or username** for Field, and **Client Code or username** for Client. Check spelling, case, and the current password. Do not keep guessing. | If you still cannot sign in, contact HR/Admin privately. They check the account status, portal role/link, and reset the password if authorized; they must not disclose the existing password. |
| **Account locked / Too many attempts** | Repeated failed sign-ins triggered a security lock or rate limit. | Stop trying and wait if the page gives a retry time. Confirm the correct portal and identifier. | Contact an authorized administrator if it remains locked. They verify identity and follow the account-unlock/reset process; do not create a duplicate account. |
| **Change password required** | A temporary password is valid only for first sign-in; the account cannot use normal features until it is changed. | Set a new private password on the displayed change-password page, then continue. | If the temporary password is lost/expired or the change fails, ask an authorized administrator for a new one. Never share it in a screenshot. |
| **Session expired / Signed out on another phone** | Your login expired, was revoked, or a newer login replaced it under the one-active-session rule. | Sign in again. If you changed phones, first consider whether old-phone punches still need syncing. | If sign-outs repeat without you logging in elsewhere, contact Admin to review account/session security. |
| **No companies assigned** | A staff account has no company grant, so there is no company dashboard to open. | Ask your Super Administrator which company you should work in. Do not use a coworker's login. | Super Admin assigns the correct company in **Users** and has you sign in/refresh again. |
| **Wrong company / Record not found / Missing menu** | You selected another company, lack a site grant, or lack a feature permission. Cross-company records are deliberately hidden. | Check the company switcher and your search filters. Do not move or duplicate a record just to make it visible. |
| **Employee or Client Code does not sign in** | The record may not have a linked portal account, may be inactive, or the code was changed. An unlinked Field Officer uses a username. | Confirm the correct portal and newest code with HR. | HR/Super Admin checks the employee/client record, active portal link and account status; creates/links the account through the proper detail page if missing. |

## Phone registration and saved punches

### “This browser was used for attendance before”

This means the Field Portal tried to register a browser ID that is already in the attendance-device history. It often happens when a Chrome profile used for **employee A** is later used for **employee B**, or when an old profile is reused after a phone change. It is **not an internet problem**. The current device policy keeps each browser ID unique, so repeated Refresh will not register that same ID. You can still read server-stored duties and earlier attendance, but this browser cannot punch until a valid attendance device is enrolled.

1. Open **Punches** and check whether this browser has any waiting or uncertain punches. If it does, **do not clear site data**. Tell your supervisor so the evidence can be handled.
2. For another employee on the same computer, use that employee's **own persistent Chrome profile** (not a shared profile or temporary Incognito window), or use their own phone. Sign in there and follow **Use this phone for attendance** if prompted.
3. If this is the employee's usual device and the warning remains, contact HR/Admin. Give the employee code, selected company, approximate time and the exact message, but not any password or browser ID.

**HR/Admin:** Verify the account-to-employee link and review the employee's attendance-device history. A phone-change **usage reset only changes the allowance**; it does not make a previously registered browser ID reusable. If another profile/phone is not practical, escalate to technical support rather than deleting device history or changing the database by hand. Resolve any missing punches with the normal attendance-review/exception process.

| What you see | Meaning and likely cause | What you should do | When to ask for help; HR/Admin action |
| --- | --- | --- | --- |
| **Use this phone for attendance** | Another device is selected, or this one has not been enrolled. Reading server history is still allowed. | First sync any saved punches on the old phone if possible. Then tap **Use this phone** on the new device. The old phone's unsynced punches do not transfer. | If the old phone is unavailable and evidence is missing, tell your supervisor. HR checks attendance/device history and handles a documented correction if justified. |
| **Phone-change limit reached** | The permitted number of phone changes has been used. It does not erase shifts or past punches. | Keep using the active phone if available. Otherwise ask HR for a verified reset; do not create a second account. | HR/Super Admin verifies the employee and, if approved, resets usage with a mandatory reason on the employee page. This does not itself change the active device. |
| **Phone change already being processed / Retry** | Two enrollment/switch requests collided or the database was briefly busy. | Wait a moment and tap **Refresh** once. Check whether this phone now says it is ready. Avoid repeated rapid taps. | If it persists, HR checks the device history and asks technical support to inspect a stuck operation. |
| **Could not check this phone** | The device-status request failed for a network, session, or server reason. The message does not mean the phone is approved. | Check internet, sign in again if prompted, then tap **Refresh**. Do not punch until the phone status is known. | If internet works but the error continues, HR/Admin checks backend availability, account link and request logs; report the time and displayed message. |
| **Punch saved on this phone / Waiting to sync** | Local evidence exists but the server has not confirmed it. | Keep the same browser data, reconnect, open **Punches**, and let it sync/check the result. Do not send a new punch just because the first is waiting. | If it remains pending or the old phone is unavailable, the supervisor reviews the server result and evidence. A saved local punch alone is not paid attendance. |
| **Pending review / Rejected** | Offline evidence needs an authorized decision, or a reviewer rejected it. | Open **Punches** for the reason. Give the event reference to your supervisor. Do not assume it is confirmed. | Attendance reviewer checks shift, site policy, location/time evidence and prior session, then records a decision or justified exception. |

## Duties, punch windows and GPS

| What you see | Meaning and likely cause | What you should do | When to ask for help; HR/Admin action |
| --- | --- | --- | --- |
| **No duty / Wrong site or shift** | No active assignment applies, today is not a selected working day, or a transfer changed the assignment. | Refresh **Home** and **Shifts**; check the local duty date, including overnight shifts. Do not punch at an unassigned site. | HR checks the current assignment, weekdays, common shift, site policy and pending transfer; corrects with the normal assignment/transfer workflow. |
| **Transfer pending / Destination not punchable** | The employee still has an open session at the original site. | Finish that site's punch-out if possible. Do not start duty at the destination in the system yet. | HR/reviewer checks the old session; a verified exception punch-out can close it and activate the transfer. Preserve old-site history. |
| **Punch in opens at … / Outside shift window** | The server's allowed punch window has not opened or has closed. Changing the phone clock will not help. | Wait until it opens. For a closed or past duty, contact the supervisor instead of trying GPS again. | HR confirms assignment and local site timezone; an authorized reviewer considers a documented correction/exception. Do not change old shifts to hide the issue. |
| **Already punched / Another active duty / Conflict** | A punch or open session already exists, or another action changed the duty while you were using it. | Open **Punches**, refresh once, and check the confirmed result. Do not repeatedly submit. | Reviewer inspects the actual session and event reference; resolves any missing punch through the approved process. |
| **Location permission denied / Location unavailable** | Browser/phone location access is blocked, GPS is off, or the phone cannot get a fix. | Enable location in phone settings, allow this site in browser permissions, move to an open area and try **Check my location**. | If the device cannot provide location during duty, notify the supervisor promptly. HR follows the documented attendance exception policy. |
| **Location requires a secure connection** | Phone/browser geolocation generally requires HTTPS (localhost is a special development exception). | Use the approved HTTPS Field Portal address, not an `http://` LAN address. | Admin/IT supplies a secure deployment or test URL; do not ask employees to bypass browser security. |
| **Location accuracy too low / Stale location** | The fix is too uncertain or old for this site's rule. For example, 138 m accuracy fails a 50 m requirement. | Stand safely in an open area at the site and request a **fresh** reading, then punch. Do not rely on the earlier map preview. | If repeated at the real duty point, HR/IT checks the site accuracy limit and tests with a real handset; do not falsify coordinates. |
| **Outside site boundary** | The phone's position plus its accuracy cannot be confirmed within the configured circle. | Move farther inside the permitted site area and retry with a fresh reading. | If the pin/radius is wrong, an authorized admin verifies the gate/post on site and creates a new geofence policy version. |
| **You are late / Reason required** | Your internal-employee punch-in is after the company policy's grace period. A reason is needed before the punch can be accepted. | Enter a truthful reason of at least 10 characters and submit the same duty punch. Do not change your phone clock. | HR checks the assigned shift, policy, and reason if the popup seems wrong. A later punch may need HR approval and a provisional half-day can appear until then. |
| **Provisional half-day / Late arrival pending** | The punch was accepted, but its late arrival exceeded the company allowance or its policy requires approval. This does not change the GPS time. | Complete the normal punch-out and check **Punches** for the decision. Do not punch again to replace the original. | HR/Super Admin reviews the late reason in **Attendance review**, then approves or rejects with a reason. Approval restores the day code; payroll consequences require separate policy approval. |
| **Map unavailable** | The optional map service/key/network failed. It is guidance, not attendance proof. | Read the duty card and address; retry map later. A fresh GPS punch can still work if its other checks pass. | Admin/IT checks map configuration, key restrictions and connectivity. Do not change punch decisions because a map failed. |
| **Server busy / Try again with same punch reference** | A simultaneous punch/attendance action or temporary database lock occurred. | Wait, refresh **Punches**, then retry using the existing in-app action rather than creating multiple evidence records. | If repeated, technical support checks concurrent requests and attendance logs; reviewer checks whether one punch was accepted. |

## Admin, HR and Client Portal

| What you see | Meaning and likely cause | What you should do | When to ask for help; HR/Admin action |
| --- | --- | --- | --- |
| **Invalid input / Field error** | A required value, format, date or number is missing/invalid. | Read the message below the field and the form summary. Correct the value and save again. | If valid data is rejected, send the field name and exact message to Admin/IT, not the full sensitive value. |
| **Code already exists / Duplicate** | Client/employee codes are unique across the group, including old reserved codes; a user link may already be taken. | Search for the existing record. Use a genuinely new approved code; never append random text to hide a duplicate person. | Super/HR verifies the correct company and existing record before deciding whether a correction or new record is needed. |
| **Client/site inactive or unavailable** | A client or site is inactive, deleted, outside the selected company, or not granted to you. | Check the selected company, record status and site search. | HR/Super Admin checks ownership, permissions and status; reactivates or corrects through normal audited actions only if authorized. |
| **Cannot create/link portal login** | The employee/client may already have an account, the candidate is linked elsewhere, or the company/role is wrong. | Check the record's **Portal account** section; do not create multiple logins for the same person/client. | HR can create an Employee or Client login from its saved detail page where permitted. Super Admin resolves existing-account replacement or scope conflicts. |
| **Document rejected / Over 5 MB** | File is too large, empty, incorrectly typed, or its contents do not match PDF/JPG/PNG. Passport photos must be JPG/PNG. | Choose a clear supported file under 5 MB; preview it and upload again. Renaming an unsupported file does not convert it. | If a valid file still fails, HR/IT checks private document storage. Do not email identity documents through an unapproved channel. |
| **Cannot view/delete/review document** | Your role lacks access, the document was removed/replaced, or the private file is unavailable. | Refresh the employee's **Documents** section and use your own authorized account. | Super Admin checks document permissions; HR/IT checks storage and audit history. Staff-reviewed means inspected, **not** KYC-verified. |
| **Exception punch-out time invalid** | The chosen actual departure time is before punch-in, in the future, or nonexistent in the site's timezone. | Verify the employee's real departure time and local date before submitting the exception reason. | An authorized reviewer checks the evidence and corrects the entered time; do not use “now” to cover a forgotten punch-out. |
| **You cannot correct your own attendance** | A Field Officer is linked to the employee whose duty they selected. Self-correction is blocked even when the officer can manage that site. | Do not use another person's login. Note the site, duty date, actual times, and reason, then ask HR to review the evidence. | An HR Administrator or Super Administrator with attendance-correction permission records the correction. The original GPS punch remains in history, and changed times are marked not GPS-verified. |
| **Client worked hours empty / Site missing** | The selected month has no completed accepted time, or the linked client has no active site in that view. Open/pending punches are excluded. | Check the month and site, then press **Show**. Worked hours are not payroll or an invoice. | Hitech Group Admin checks client-to-account link, site ownership/status and completed sessions; they must not grant another client's site. |
| **Save blocked / Permission denied** | Your role, company grant or site scope does not allow the action. | Confirm the selected company and ask for only the access your job needs. | Super Admin reviews the role and grant; HR/Field Officer must not use someone else's account to bypass the restriction. |

## Leave and attendance reports

| What you see | Meaning and likely cause | What you should do | When to ask for help; HR/Admin action |
| --- | --- | --- | --- |
| **Leave menu missing** | The linked employee is not marked **Leave applicable**, or the eligibility request could not load. | Check that you are signed in to your own Field Portal account and online, then refresh once. | HR checks the employee link, selected company, eligibility and active policy. Do not grant a leave role to another person to make the menu appear. |
| **No active leave policy / Leave unavailable** | HR has not signed off and applied a policy to the employee's current company for the requested dates. | Do not submit under another company. Give HR your company and intended leave dates. | HR reviews **Common → Leave policies**, the approved version, effective date and company application. |
| **Leave request cannot be sent** | The dates may be out of order, longer than 31 days, across a leave-year/policy change, lack an assignment, or the reason is too short. Submission also requires internet. | Read the field error, use the correct dates and a reason of at least 10 characters. Split a request at a leave-year or policy boundary. | HR checks the assignment, policy calendar and eligibility if valid dates still fail. A request is not an approved absence. |
| **Opening balance required / Insufficient balance** | HR has not opened the requested CL/SL/PL balance for that leave year, or its remaining days are too low. | Keep the request reference; do not submit duplicates to increase the balance. Contact HR. | HR opens a reasoned balance or records an approved adjustment on **Employees → employee details → Leave**, then reviews the same request. No automatic credits occur. |
| **Leave approval conflict / Request changed** | Attendance, another leave request, a day classification, the assignment, or policy/holiday dates changed since submission. | Refresh **My requests** and tell HR which dates are affected. Do not make another punch to clear the conflict. | HR checks **Leave requests** and the source attendance/calendar. If the snapshot changed, the employee may need to send a new request. |
| **Transfer review** | A future leave request moved with an employee to a different company and needs the destination policy/calendar checked. | Wait for destination HR's decision; prior approval does not carry automatically. | Destination HR reviews eligibility, dates and carried balance before approving or rejecting. Earlier approved days remain with the old company. |
| **Report has `?` / Cannot finalize** | One or more duty dates have missing or conflicting attendance/leave evidence, or the period has not ended. `?` is not an absence code. | Note the site, employee and work date shown below the preview table. | HR resolves the source day in **Attendance review** or **Leave requests**, previews again and finalizes only after all issues are clear. Worked holidays need an agreed coding rule. |
| **Saved report differs from current attendance** | A correction, leave decision or day decision occurred after that report version was saved. Saved versions do not rewrite themselves. | Do not edit or circulate the old download as a new report. Tell HR the report version and changed date. | Authorized HR/Super staff reopens the report with a reason, checks source days, previews and finalizes a new version. |
| **Report PDF/Excel download unavailable** | The report has only been previewed, the account lacks report access, or the download failed. | Open a **Saved report version** and try its PDF/Excel button once. | HR checks finalization, company access and report permission; IT checks a persistent download error. Word export is not available yet. |

Do not copy old-company private documents across company boundaries to bypass access rules. |
| **Grievances or notice inbox unavailable** | The Field Portal login may not be linked to an active employee record, the session may have expired, or the request could not load. This does not automatically resolve or escalate the case. | Open the case history and send a reply while it is open. For urgent safety matters, use the direct supervisor or emergency process as well. | Company HR assigns a handler, replies and records a resolution with a reason. | **Notice missing / Bell count seems wrong** | The inbox needs internet; the notice may be for different recipients, already opened, or withdrawn. A later site/company transfer does not change the saved audience. | Refresh the bell online and check your own account. ## If the error is not listed

For a temporary network or **server error**, check your connection, wait briefly and retry once. Do not keep submitting the same form or punch if the result is uncertain. A **404/not found** may mean the record belongs to another company or was removed; a **403/forbidden** means your account does not have access. A **409/conflict** usually means the record changed or another request already completed; refresh and inspect the latest state. A **500/503** that continues needs Admin/IT investigation. Do not attempt database changes or browser-data deletion to “fix” these errors.

When contacting HR/Admin, provide: portal and page, selected company, employee/client code, site, local duty date and time, exact visible message, and what you tried. For an uncertain punch, provide the event reference from **Details for supervisor** if shown. Admin/IT should use that reference and server audit logs to check the result before asking for another punch. Send any sensitive documents only through the approved HRMS flow.
